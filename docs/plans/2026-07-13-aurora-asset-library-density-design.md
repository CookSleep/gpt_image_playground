# Aurora 图片资产页密度与可读性优化设计

## 背景

线上巡检确认图片资产页同时存在视觉密度和交互可靠性问题：

- 1536px 桌面视口中，首张卡片从页面顶部约 355px 开始；390px 移动视口中约为 533px。
- 搜索框最大宽度固定为 620px，大屏工具区右侧存在大面积无效空白。
- 图片提示词固定裁为两行、约 34px；线上样本完整内容实际需要 68-188px。
- 图片名称固定单行省略，长名称缺少完整可见入口。
- 移动端文件夹和卡片操作按钮仅 32-34px，不适合作为高频触控目标。
- 快速切换搜索或文件夹时，旧请求可能晚于新请求返回并覆盖最新筛选结果。
- 搜索、创建文件夹、文件夹导航和结果统计分散在多个水平层级中。

## 目标

1. 提高桌面与移动端首屏信息密度，减少无用途留白。
2. 保留图片浏览属性，同时让名称和提示词具备足够的可读性。
3. 让搜索、文件夹导航和资产操作形成清晰的信息架构。
4. 修复资产请求乱序导致的筛选结果回退问题。
5. 保持现有后端 API、数据库、对象存储和删除语义不变。

## 非目标

- 不新增排序、标签、嵌套文件夹或新的后端字段。
- 不修改图片生成、任务详情、批量移动和删除确认业务规则。
- 不裁剪原图来换取视觉铺满；缩略图仍应完整展示图片内容。

## 方案选择

采用桌面两列横向资产卡片、移动端单列竖向卡片的平衡方案。

未采用仅压缩现有竖向网格的方案，因为它无法充分解决宽屏留白和文案可读性。未采用表格加详情抽屉方案，因为它会削弱图片资产的视觉浏览体验，并扩大交互复杂度。

## 页面结构

### 页头

- 保留“图片资产”标题与一句说明，压缩上下内边距和标题区高度。
- 右侧保留刷新与“创作新图片”两个操作。
- 刷新使用熟悉图标和工具提示；“创作新图片”继续作为主操作。

### 桌面内容区

```text
[图片资产 + 说明]                         [刷新] [创作新图片]

[文件夹        +] | [搜索图片名称或提示词.............] [结果数量]
[全部图片]       | [横向卡片] [横向卡片]
[未分类]         | [横向卡片] [横向卡片]
[自定义文件夹]   |
```

- 文件夹栏宽度由 232px 收敛到约 188-200px。
- “创建文件夹”移动到文件夹栏标题旁，明确其所属关系。
- 搜索框与结果数量放入结果区顶部，搜索框使用结果区可用宽度。
- 宽屏使用两列横向卡片；中等宽度使用单列横向卡片。

### 移动端内容区

- 页头、主操作、搜索、文件夹选择器按紧凑节奏排列。
- 卡片改为单列竖向结构，保证图片预览宽度和文案阅读宽度。
- 第一张卡片目标在页面顶部约 360px 内出现。
- 高频触控按钮最小尺寸为 40px。

## 资产卡片

### 桌面

- 左侧为 180-200px 缩略图，保持完整图片内容，点击进入任务详情。
- 右侧依次展示名称、提示词和操作区。
- 名称最多两行，并使用 `title` 暴露完整名称。
- 提示词默认三行，提供独立的“展开/收起”操作。
- 文件夹选择、重命名和删除位于稳定的底部操作区。
- 复选框继续覆盖在图片左上角，但交互区域扩大。

### 移动端

- 图片位于卡片顶部，名称、提示词和操作区依次排列。
- 展开提示词只影响当前卡片，不改变其他卡片状态。
- 文件夹选择与重命名、删除按钮保持单行，按钮最小 40px。

## 状态与数据流

### 提示词展开状态

- 组件维护展开图片 ID 集合。
- “展开/收起”按钮使用 `aria-expanded`，并关联对应提示词区域。
- 资产列表变化时，不要求持久化展开状态。

### 请求防乱序

- 每次资产请求开始时分配递增请求序号。
- 只有当前最新序号对应的请求可以写入资产列表、错误和加载状态。
- 搜索、文件夹切换、刷新和分页共用同一请求防乱序机制。
- 旧请求完成或失败时直接忽略，不覆盖最新结果，也不关闭最新请求的加载状态。
- 筛选更新期间保留当前列表，并显示轻量“更新中”反馈，避免内容闪空。

## 错误处理

- 只显示最新资产请求产生的错误。
- 文件夹和图片写操作错误维持现有错误提示方式。
- 空搜索结果继续给出更换关键词提示；空文件夹继续说明可移动图片或开始创作。
- 不改变删除确认弹窗与对象存储删除失败时的现有保护行为。

## 响应式规则

- 大于 1100px：两列横向资产卡片。
- 761-1100px：单列横向资产卡片。
- 不大于 760px：单列竖向资产卡片，文件夹使用下拉选择器。
- 390px 视口无横向溢出，所有文字和按钮不得相互遮挡。

## 测试与验收

### 自动化测试

- 请求序号守卫必须拒绝旧请求更新，并允许最新请求更新。
- 提示词展开状态必须按图片独立切换。
- CSS 契约覆盖桌面两列横向卡片、中屏单列横向卡片和移动端竖向卡片。
- CSS 契约覆盖名称两行、提示词三行、展开态和移动端 40px 触控尺寸。
- 保持现有资产搜索、文件夹、命名、移动、删除和视觉规范测试通过。

### 浏览器验收

- 视口：1536px、1100px、760px、390px。
- 检查首张卡片位置、卡片几何结构、长名称、长提示词展开/收起和横向溢出。
- 快速连续切换全部图片、未分类和自定义文件夹，最终结果必须与最后一次选择一致。
- 连续输入搜索关键词，最终结果必须与最后一次搜索一致。
- 检查批量选择、重命名、移动和删除确认入口布局，但不删除用户数据。

## 部署约束

- 先运行前端全量测试、生产构建和 `git diff --check`。
- 部署前逐个核对服务器目标文件并创建精确备份，不覆盖未知修改。
- 只部署本轮必要的前端文件；Compose 若因依赖关系重建后端，需确认后端源码未变。
- 上线后检查前后端容器状态、重启次数、健康接口和真实浏览器页面。
- 不触发线上付费图片生成。
