# Aurora 资产管理与双 Key 设置设计

## 目标

在保持现有 Aurora Studio 登录、图片生成、PostgreSQL 持久化和 S3/MinIO 存储行为的基础上，补齐以下产品能力：

- Aurora 品牌文案和控制台入口
- 图片独立命名、搜索和一级文件夹归类
- 图片、任务和文件夹的确认删除
- 删除生成图片时同步清理对象存储
- 在设置中心保存图片生成 Key 和提示词优化 Key
- 使用独立 Key 和 `gpt-5.5` 优化生图提示词

后端 API 继续实时读取，不引入响应缓存。本地验证使用 mock 上游，不主动触发线上付费生成。

## 已确认的业务规则

### Aurora 入口

- 登录文案改为“使用你的 Aurora 账号进入私人图片空间。”
- 登录邮箱占位文案使用 Aurora 品牌。
- 登录页和账号不可用页均提供 `https://x.wfjpg.cc/` 控制台链接，并在新标签页打开。

### 双 Key 设置

- 设置中心分别保存“图片生成 Key”和“提示词优化 Key”。
- 两个 Key 都从当前 Aurora/sub2api 账号的 Key 列表选择。
- PostgreSQL 仅保存 Key ID，不保存 Key 明文。
- 图片生成 Key 不再在创作区临时选择。
- 两个 Key 未完整配置时，图片生成和提示词优化均不可用。
- 提示词优化默认使用 OpenAI-compatible Responses API 和模型 `gpt-5.5`。

### 图片与文件夹

- 每张图片有独立名称；提示词保留为生成信息，不再充当图片标题。
- 默认名称为 `Aurora 图片 YYYY-MM-DD HH:mm`，同一任务多图追加 `- 1`、`- 2`。
- 图片支持重命名。
- 仅支持一级文件夹，不支持嵌套。
- 一张图片同一时间只能属于一个文件夹；无文件夹时归入“未分类”。
- 支持单张和批量移动图片，也支持移回“未分类”。
- 搜索只匹配图片名称和原始提示词，不匹配文件夹名。

### 删除

- 所有删除操作必须经过确认弹窗。
- 删除单张图片时只删除该图片和对象存储文件，任务保留。
- 删除任务时删除任务及其全部图片和对象存储文件。
- 生成中的任务不可删除。
- 删除文件夹时提供两个选择：
  - 仅删除文件夹，图片移回“未分类”
  - 删除文件夹及其中图片，同时清理对象存储；关联任务保留
- 删除任务最后一张图片后，任务保留并显示“图片已删除”。

## 数据模型

### `user_settings`

- `user_id`：主键并关联 `users(id)`，用户删除时级联删除。
- `image_api_key_id`：图片生成 Key ID，可为空。
- `prompt_api_key_id`：提示词优化 Key ID，可为空。
- `created_at`、`updated_at`。

前端只能获得 Key ID 和有效状态。每次生成或优化时，后端通过当前 sub2api 会话实时解析 Key 明文。

### `asset_folders`

- `id`
- `user_id`
- `name`
- `created_at`、`updated_at`

同一用户下文件夹名称去除首尾空格后不可重复。所有查询和修改必须同时校验 `user_id`。

### `generation_images`

新增：

- `name`：独立图片名称，非空。
- `folder_id`：可为空，关联 `asset_folders(id)`，文件夹删除时默认 `set null`。

现有图片迁移时按创建时间生成默认名称。同一生成任务有多张图片时追加序号。对象存储 key 不迁移。

## 后端接口

### 设置与提示词优化

- `GET /api/settings`
- `PUT /api/settings`
- `POST /api/prompts/optimize`

保存设置时验证两个 Key 均属于当前账号且为 active。模型能力不通过付费调用预检，实际调用失败时返回上游错误并保留设置。

提示词优化请求只包含当前提示词，返回 `optimizedPrompt`。系统指令要求保留用户原意、补足适合图片生成的视觉信息，并只返回可直接使用的提示词正文。

### 文件夹与资产

- `GET /api/folders`
- `POST /api/folders`
- `PATCH /api/folders/:id`
- `DELETE /api/folders/:id?deleteImages=true|false`
- `GET /api/assets?q=&folderId=&cursor=&limit=60`
- `PATCH /api/images/:id`
- `POST /api/images/move`
- `DELETE /api/images/:id`
- `DELETE /api/generations/:id`

`GET /api/assets` 按当前用户分页查询。`q` 只匹配图片名称和所属 generation 的原始提示词。`folderId` 支持具体文件夹和未分类。

### 生成流程

前端不再传 `apiKeyId`。后端按以下顺序处理：

1. 读取用户设置。
2. 确认图片生成 Key 和提示词优化 Key 均已配置。
3. 从 sub2api 实时读取图片生成 Key，确认 active。
4. 创建 generation，保存实际 Key ID/名称快照。
5. 调用图片上游。
6. 上传对象并创建带默认名称的 `generation_images` 记录。

## 对象存储一致性

S3 适配器新增 `deleteObject`。对象不存在视为成功，其他异常向上抛出。

删除图片、任务或“文件夹及图片”时，后端先列出当前用户拥有的目标记录和精确 object key，再同步删除对象。只有所有相关对象删除成功或确认不存在后，才删除数据库记录。若批量删除中有对象失败，返回失败项并保留对应数据库记录，允许幂等重试。

生产部署前仍须对服务器上的精确修改文件做时间戳备份，不执行 `git pull/reset/checkout`，不覆盖未知改动。

## 前端交互

### 设置中心

顶部工具栏增加设置图标。设置弹窗包含两个 Key 下拉框和统一保存操作，并显示 Key 已失效或不存在的状态。

未配置完整时，创作区显示配置引导并禁用生成和提示词优化。点击引导直接打开设置弹窗。

### 提示词优化

提示词输入区增加“优化提示词”操作。请求完成后打开对比弹窗，保留原文并展示优化结果。只有点击“应用优化”才替换草稿，取消时不修改。失败时保留原文并允许重试。

### 资产管理

桌面端使用左侧文件夹导航和右侧资产网格；移动端使用紧凑文件夹选择器。资产顶部提供搜索、创建文件夹和多选入口。

图片卡片以图片名称为主标题，提示词为次要信息。单张支持详情、重命名、移动和删除。多选后显示固定批量工具栏，支持移动到文件夹或未分类。

文件夹支持创建、重命名和删除。删除弹窗明确区分“仅删除文件夹”和“删除文件夹及其中图片”。图片和任务删除使用独立确认弹窗。生成中任务不提供可用删除操作。

## 错误处理与安全

- 所有资源接口按当前用户隔离，不能只凭资源 ID 操作。
- 文件夹名和图片名去除首尾空格并限制长度。
- 空名称、同名文件夹、无效 Key、无权访问、生成中任务删除和对象存储错误均返回明确中文错误。
- 前端请求继续使用 `cache: 'no-store'`。
- 设置响应、日志和错误不得暴露 sub2api access token、refresh token 或 API Key 明文。
