# Aurora 参考图数量与大小限制设计

## 背景

Aurora 创作工作台当前只读取每次选择的前 4 张图片，并用新选择覆盖已有参考图。OpenAI GPT Image 与线上 sub2api `0.1.144` 均支持最多 16 张输入图片，因此现有 4 张上限属于前端限制。

## 目标

1. 参考图上限提高到 16 张。
2. 单张文件最大为 4 MiB，即 `4 * 1024 * 1024` 字节。
3. 支持多次选择并追加参考图。
4. 前端提供即时反馈，后端提供不可绕过的硬校验。
5. 保持生成参数、任务持久化、对象存储和 sub2api 转发行为不变。

## 交互规则

- 每次选择文件后，合规图片追加到当前参考图列表。
- 单张超过 4 MiB 的图片跳过。
- 合规图片超过剩余名额时，只加入可容纳的部分，其余跳过。
- 同一批中存在跳过项时，以一条汇总错误说明超大文件数和超出名额数。
- 达到 16 张后禁用添加按钮。
- 缩略图使用横向滚动，避免 16 张图片撑宽创作侧栏。
- 保留现有“清空全部”操作，不新增排序、单图删除或图片压缩。

## 前端结构

- 新增纯逻辑模块，集中定义 `16` 和 `4 MiB` 两个约束，并规划一次文件选择的接收与跳过结果。
- `App.tsx` 使用规划结果读取合规文件，再通过函数式状态更新追加 Data URL。
- 页面文案调整为“最多 16 张 · 单张不超过 4MB”。
- 文件输入保持多选；达到上限时添加按钮禁用。

## 后端校验

- 在创建任务之前校验 `inputImages`。
- `inputImages` 必须是数组；最多 16 项。
- 每项必须是合法 Data URL，解码后不得超过 4 MiB。
- 16 张 4 MiB 图片编码为 JSON Data URL 后会超过原 80 MiB 请求体限制，因此 Fastify `bodyLimit` 与 Nginx `client_max_body_size` 同步提高到 92 MiB；单图和数量校验仍以解码后的实际字节数为准。
- 任何后端校验失败均返回 `400`，不创建生成任务，也不调用 sub2api。
- 校验通过后继续使用现有 `imageClient.generate` 和 `/v1/images/edits` 转发链路。

## 错误处理

- 前端选择阶段允许部分成功，错误提示不会清除已加入图片。
- 后端请求阶段采用整批拒绝，防止绕过前端限制。
- 文件读取失败沿用当前页面错误区域，不影响已有参考图。

## 测试

- 前端纯逻辑测试：追加、4 MiB 边界、超大跳过、剩余名额截断。
- 后端接口测试：16 张接受、17 张拒绝、4 MiB 接受、超过 4 MiB 拒绝、非法 Data URL 拒绝，并确认拒绝时不创建任务。
- 页面契约测试：16 张文案、追加状态写法、按钮禁用和横向滚动。
- 最终执行前后端全量测试、生产构建和浏览器验证。
