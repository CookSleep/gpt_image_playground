## Context

项目工作区当前由 `TaskGrid` 以任务卡片网格展示内容；一个 `TaskRecord` 可以包含多张 `outputImages`，而现有收藏、删除、复用和编辑操作也主要以任务为单位。图片缩略图、原图缓存、Lightbox、筛选器和 Agent 工作区已经存在，可以作为画布的基础能力。

新画布需要同时满足桌面端和触控端的平移/缩放，且不能因为把多图任务拆成多个持久化任务而破坏 Agent 输出引用、任务历史或在线归档。

## Goals / Non-Goals

**Goals:**

- 在项目页左侧提供可平移、缩放、拖动节点的无限画布。
- 将每张输出图作为独立的图片对象展示和操作，保留生成中、失败状态。
- 保持现有搜索、筛选、Lightbox、Agent 面板和输入流程可用。
- 持久化项目视口、图片位置/尺寸和单图收藏状态，兼容本地、导入导出和在线归档。
- 支持从多图任务中删除单张输出，并维护透明背景元数据和 Agent 引用稳定性。
- 缩小纯文本提示输入区域的默认高度。

**Non-Goals:**

- 不在本次变更中实现多人协作、评论、连线或画布内容编辑。
- 不改变图像生成 API 的批量请求能力。
- 不把一个父任务物理拆成多个新的 `TaskRecord`。
- 不将参考图作为独立画布节点。

## Decisions

### 1. 在界面层单图化，保留父任务

从任务输出数组派生稳定的画布图片对象，键使用 `imageId`，并保留 `taskId`、输出索引和任务元数据。完成多图请求后，每张图独立渲染和操作；底层任务仍保留原始请求、提示词、参数、Agent 关联和批量错误信息。

物理拆分任务会破坏 `AgentRound.outputTaskIds`、原始响应和历史任务语义，因此不采用。

### 2. 项目内保存画布状态

在 `Project` 中增加可选的画布状态字段，包含版本、视口和按图片 ID 索引的节点布局及单图收藏夹。节点布局使用世界坐标；视口变换只影响渲染，不改写图片原始尺寸。

```text
canvas: {
  version,
  viewport: { x, y, scale },
  items: {
    [imageId]: {
      x, y, width,
      favoriteCollectionIds
    }
  }
}
```

新增图片没有布局时按确定性网格放入下一个空位；已有布局优先保留。加载时清理不存在图片的陈旧布局。

### 3. DOM 节点 + 世界坐标变换

画布使用可滚动裁剪容器和绝对定位 DOM 图片节点，节点容器统一应用 `translate/scale` 世界变换。背景空白区域负责平移，滚轮和双指手势围绕指针/中心点缩放。工具条使用屏幕像素尺寸，通过选中节点的视口矩形定位在图片上方，因此缩放时不会变得不可用。

不引入第三方画布库；复用现有图片缩略图缓存和 React Pointer Events。大量节点时只挂载视口附近的节点，避免一次解码全部原图。

### 4. 单图操作适配现有任务 API

所有工具条动作接收 `imageId`，通过图片对象反查父任务。查看、下载、复制、加入参考图、保存素材只处理该图片；复用配置和重试使用该图片所属任务的配置，但不携带同任务其他输出；编辑输出只把当前图片加入输入。

收藏状态从任务级扩展为图片级，画布和收藏夹视图按图片对象计算。为兼容旧数据，旧任务收藏状态在加载时可映射到其所有输出图片，之后的新操作只写入图片级状态。

### 5. 单图删除和引用稳定性

删除操作从父任务的 `outputImages` 移除目标图片，并同步移除同索引的透明背景原图、单图参数和修订提示词；`outputErrors` 的索引也必须重算。若删除最后一张输出，保留父任务记录但不生成画布节点。

Agent 轮次的输出槽位不能因删除中间图片而重新编号。对已被 Agent 引用的输出保留删除槽位或等价的稳定映射，使历史引用显示为已删除而不是指向另一张图片。图片只有在不再被任务、Agent、输入草稿或画布状态引用时才清理本地和在线存储。

### 6. 持久化与同步

扩展项目规范化、IndexedDB 项目记录、ZIP manifest 和在线项目归档构建/读取，使旧项目无 `canvas` 字段时使用默认视口和自动布局。画布状态变更通过现有项目持久化队列触发在线归档同步；单图删除复用现有在线项目图片删除和孤立图片清理机制。

## Risks / Trade-offs

- [大量图片导致 DOM、缩略图解码和布局计算变慢] → 使用缩略图、视口裁剪和稳定的节点尺寸，必要时按世界坐标进行可见性筛选。
- [单图收藏与旧任务收藏数据不一致] → 提供加载迁移规则，旧任务收藏映射到输出图片，并让后续写入使用图片级字段。
- [删除 Agent 输出后引用编号变化] → 保留输出槽位/稳定映射，并为删除引用提供明确的已删除状态。
- [在线归档或旧导入文件不包含画布字段] → `canvas` 设为可选，读取时回退到默认布局，写入时带版本号。
- [画布拖动与既有框选/点击事件冲突] → 画布使用独立指针状态机，节点操作区域标记为非画布拖动区域，只有明确的背景拖动才启动平移。

## Migration Plan

1. 增加可选画布数据结构和规范化/导入导出兼容逻辑，不影响旧项目读取。
2. 实现画布派生图片对象、视口交互、默认布局和单图选择工具条。
3. 增加单图收藏与单图删除动作，更新收藏夹和 Agent 引用处理。
4. 将项目页主区切换到画布并调整纯文本输入区域高度。
5. 通过构建、单元测试和手动桌面/移动端交互验证后发布。

回滚时可让项目页继续使用旧任务网格；新增的 `canvas` 字段保持可选，不影响旧数据和任务记录。

## Open Questions

无。工具条固定屏幕尺寸、删除最后一张输出后保留父任务、以及参考图只出现在图片信息中均按已确认的默认行为执行。
